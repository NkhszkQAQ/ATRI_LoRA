## 当前调用与权限

既有记忆 `plan` 和实际操作位置保留，仅执行一次。独立 `lookup_plan` 使用底座、关闭角色LoRA，先判断是否需要角色原作资料，再选择当前阶段的资料主题。用户原话由程序保留为n1，不让模型改写主体、否定或增加需求。

- `null` 表示不需要原作资料：跳过实际RAG和资料检查，交接为 `not_needed`；实际记忆操作结果照常保留。
- JSON字符串数组表示需要资料。没有匹配主题可用 `[]`，仍按原话检索。程序只接收已核验、阶段内的主题ID，最多执行前2个；超额提议及拒绝原因记录在 `topic_decision`，不会增加额度。未知ID、错误类型或超过64个原始提议会拒绝。
- StageCorpus标题只作入口，不作证据。Runtime再次核对阶段，最多64个标题、单项160字符、合计2000字符。自定义受信回调没有主题接口时仍可按原话查。

首次检索使用原话、近期用户上下文和获准的主题查询。所有补查沿用原作SHA/场景校验、阶段过滤、原重排阈值、合并排序及上下文预算；不扩大原话dense补充权限。身份、阶段、额度和预算不由模型或请求body决定。

资料检查分成小任务，均关闭LoRA：

1. 对预算内排名靠前的资料逐条判断是否直接支持当前问题的至少一部分，只收JSON布尔值。最多检查16条，按当前问题、来源ID及完整文本缓存本轮判断，补查不重复检查同一资料。
2. 对通过的资料判断是否覆盖全部所问事实，返回实际来源ID与sufficient布尔值。明确不会做饭足以回应拒绝任务，部分恢复足以回答并非全部恢复；不能把能力限制当作资料未知。无支持资料时程序直接判不足，不能硬选同角色的其他经历。
3. 只有资料不足且仍允许检索时，再提出 `unresolved_span` 和至多2条查询。缺口片段必须逐字出现在原话、非空且最多300字符；改写或新增地区、权限等条件会被拒绝，程序保守保留整个原问题的未确认状态。原提议及拒绝原因仍保存。检索结束后不再调用查询规划器，沿用已验证片段或原问题。

查询只是提议。程序独立校验类型、长度和额度，仅在存在必要缺口且允许检索时接收，`query_decision`分别保留proposed、admitted和rejection_reason。拒绝查询不等于丢弃已通过来源校验的事实；真正有缺口却没有可执行查询时仍记录planner_no_query，不能算资料齐全。未知字段、伪造来源、重复JSON字段、错误布尔类型及无来源无缺口等不会被当作有效事实安排。

最多额外两轮，每轮最多两个查询，**首次检索批次不计入**。重复规范化查询、无新增准入资料、检索失败或次数用尽后停止，保留实际未知。补查和资料检查没有写入、更正、删除入口，不会重做记忆操作。

## 两层交接

`answer_plan`由程序组装，仍为v2。模型不能自行编事实摘要或操作成功状态。

| 内容 | 约束 |
| --- | --- |
| `must_respond` | 复制实际资料的完整fact、source_id和evidence，只能来自通过本轮资料检查的来源。 |
| `optional_reference` | 来源绑定格式相同，可为空；当前实验优先保留直接支持问题的必需资料。 |
| `fact_boundaries` | 保留完整命题中的主体、否定、程度，附阶段、事件时间、揭示时间和知识状态。 |
| `information_gaps` | 绑定原问题及已校验的原话片段；未查明不是不存在。不能把模型新猜的条件交给回答层。 |
| `operation_results` | 复制实际执行trace，去除随机数据库ID；提议不等于成功。 |

另附information_needs、coverage、story_stage和stop_reason。未选中或未通过支持检查的命中只留在审计日志，不再混入角色上下文。完整事实、出处和交接共用7000字符预算，并预留缺口与原问题绑定的空间；不截断已选事实。模型输入仍受8192 token保护。

最后使用原LoRA回答一次，原始首答直接返回，不重答、不筛选、不做事实后处理。角色仍自然聊天，不朗读字段、查询或检查过程。HTTP/SSE只返回角色答复，内部提议保存在私有trace。资料布尔判断仍可能出错，合法ID及程序审计不等于语义正确，必须另做实际资料核对。

## 重放与真实诊断

`tools/eval_answer_planning.py`的replay/real互斥。replay必须显式提供lookup及分任务review夹具：每例包含source_support来源布尔映射、rounds中的evidence，以及需要时的missing（unresolved_span/queries）。旧status、checks或整体四字段夹具不自动当作新模型结果。real模式拒绝夹具和历史目录，要求execute、底座manifest、适配器SHA及明确路径。`tools/eval_planner_only.py`的base_only诊断拒绝LoRA和角色回答；generate_answer=False只由程序控制，HTTP body不能启用。

真实运行保留查询、实际命中、各子任务的完整模型输入/首答、来源安排、token、adapter状态及虚构用户库前后状态。各失败候选单独保留，不把不同新题的总分直接比较，也不挑最好的一次首答。功能默认关闭，正式采用、训练与部署另行决定。
