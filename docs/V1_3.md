# v1.3 服务修复候选版

v1.3.0 指 8B 独立服务的运行时版本。仍加载 Qwen3-8B + 原 v1.1-R LoRA；没有训练、修改或重新命名 adapter。Colab、4B 与完整版 backend 不自动获得这些改动。当前为待真实 GPU 验收的候选版，未发布或部署。

## 修复范围

此前真实 8B 测试发现：正确召回资料后，仍把不擅长家务说成会料理；学校动机漏掉寻找记忆；空检索仍编造充电设定；混合提问漏答用户偏好或将其写成 ATRI 的偏好；凭空添加称呼、误写角色名字。

本版在回答阶段处理这些问题：

- 修正系统人设中不能进食及无依据的供电表述。有事实卡时优先使用该卡的完整概括，不混入其他剧情阶段的原始对白。
- 每张事实卡附必要要点与已知矛盾的正则检查。生成后检查，失败最多重答一次；仍失败则使用已核对的事实概括。未配检查的事实卡直接使用来源概括。
- 角色规格问题如没有对应已核实事实，明确表示不能确认。已识别的角色事实问题无检索命中时也明确表示未知。
- 明确分开的多个问题逐项处理，每次最多六项；超出时要求分批提问。已保存的用户信息直接按当前认证用户读取并标明归属，不交给模型改写成自身偏好。
- 当前会话中明确的偏好或称呼纠正可以用于回答，但不会暗中写入 SQLite；询问已保存信息时区分保存值和本轮纠正。普通聊天子问题仍使用原长期记忆注入逻辑。
- 清理模型输出中的常见角色名误写及上下文未提供的“某某先生/小姐”称呼。保存的用户值不经此清理。

长期记忆的认证、表结构、保存/忘记/清空命令不变。记忆命令仍在检索、生成前执行；普通聊天不自动保存，RAG 不读取其他用户的数据。

这属于有限领域的回答约束，不是通用语义校验。正则不能发现所有矛盾；未整理为事实卡的原始剧本问题、复杂指代、多意图及未识别问法仍可能出错。事实卡回退会比较书面，不能把回退率当作模型本身的正确率。

## 配置与迁移

按 [RAG 安装说明](RAG.md)准备依赖。资料与索引保留在私有目录。必须新建索引，以包含完整事实概括与检查配置；不覆盖旧目录：

```bash
python tools/atri_rag.py build \
  --source /path/to/original-scripts \
  --storage ./rag_storage-v1.3 \
  --persona ./persona \
  --facts ./rag/character_facts.json

export ATRI_BASE=/path/to/Qwen3-8B
export ATRI_ADAPTER=/path/to/existing-v1.1-R-adapter
export ATRI_SYSTEM="$PWD/persona/system_prompt.txt"
export ATRI_RAG_ENABLED=1
export ATRI_RAG_STORAGE="$PWD/rag_storage-v1.3"
export ATRI_GROUNDING_ENABLED=1
# 如需长期记忆，按 LONG_TERM_MEMORY.md 配置独立用户密钥与数据库。
python tools/serve_v1_1_8b.py
```

| 配置 | 行为 |
| --- | --- |
| `ATRI_RAG_ENABLED=0`（默认） | 不加载 LlamaIndex、embedding 或重排器 |
| `ATRI_MEMORY_ENABLED=0`（默认） | 不加载长期记忆 |
| `ATRI_GROUNDING_ENABLED=1`（默认） | RAG 或记忆开启时使用本版回答流程 |
| `ATRI_GROUNDING_ENABLED=0` | 保留旧注入流程，不能据此视为 v1.3 修复生效 |
| `ATRI_MODEL_NAME` | 默认 `atri-v1.3-8B`；可覆盖客户端使用的模型名 |

旧索引缺少完整事实概括时，回答约束开启的服务会明确启动失败并要求重建。入口先验证索引和记忆配置，再加载 CUDA 模型。恢复旧索引和旧流程时可关闭回答约束；数据库无需迁移。

JSON 与 SSE 仍使用 `/v1/chat/completions`。`/health` 增加 `runtime_version`。受约束的请求增加可选 `atri` 字段：每项问题的 `kind`、采用 `model` / `repair` / `source_fallback` / `source_reference` / `direct_reference` 哪种回答方式、生成次数与内部生成 token 数。不返回用户密钥或整份记忆。SSE 在最后的完成事件附该字段，之后发送 `[DONE]`。

事实回答先完成检查再流式发送，因此首字延迟可能增加；普通聊天按完整句子清理称呼后输出。`max_tokens` 约束最终可见答案，超出时截断并标为 `finish_reason=length`。重答会消耗额外内部生成量，记录在 `atri.internal_completion_tokens`；标准 `usage.completion_tokens` 统计最终可见答案。

## 当前验证与剩余验收

本地使用真实中文 embedding 与 CPU 重排器，新索引的既有 58 题检索回归全部通过。这只衡量命中，不能代表生成正确率。测试集已用于开发，不是独立准确率基准。

103 项自动化测试通过，覆盖已观察坏草稿的拒绝与回退、事实卡检查一致性、JSON/SSE 输出、双用户认证/隔离、普通聊天的记忆注入、当前纠正不落库、命令旁路及真实落盘格式的旧索引拒绝。接口测试使用替代生成模型，不能代替真实 LoRA。

真实 GPU 验收尚未执行：需要对料理、学校、未知设定、称呼与多问题回答做多个 seed 和新问法的人工复核；共同开启 RAG 与长期记忆，检查真实 HTTP/SSE、用户隔离、删除与独立进程重启保留，并记录重答及来源回退比例。此前旧版的真实 8B 失败记录见 [RAG 第四轮记录](RAG.md#第四轮真实8b-lora与长期记忆组合测试2026-11-05)，不能作为本候选版已通过的证据。
