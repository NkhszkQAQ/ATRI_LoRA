## 数据与职责

| 层 | 负责内容 |
| --- | --- |
| `atri_memory_lifecycle` | SQLite 所属用户隔离、当前事件去重、原子保存/更正/删除、重要性/确认时间/重复确认评分 |
| `atri_runtime` | 同一 8B 分析上下文、选择记忆、提出查询和候选；程序检查证据并执行，再把实际结果交给角色回答 |
| `atri_story` | 核对原作文件 SHA 与场景出处，先按角色实际知识阶段过滤，再用本地交叉编码器重排 |
| 各入口 | 从 Bearer、网页 JWT 或 QQ 签名取得身份；分别保留会话及数据库，不接受模型或 body.user 指定所属用户 |
| `atri_generation` | 同一底座内部规划默认临时禁用角色 LoRA；最终回答启用原有 1.1-R。锁内恢复适配器，保存首次输出及 token |

默认保存门槛为 `.8`，另要求稳定性至少 `.7`；入库评分为 `.5×明确度 + .35×稳定性 + .15×重要性`。明确一次的重要事实可以保存。偏好、名字和过敏保留专用类型；其他稳定个人信息可由规划器提出 `statement` 候选，要求完整当前原话、明确主体、重要性与稳定性分数，再由程序检查及准入。策略排除引用、玩笑、临时选择、助手建议及不确定分析；实际覆盖仍受模型框架分类和程序已识别语法限制，不能视为所有自然语言场景的保证。

新事实准入与明确更正分开处理。当前自陈通过证据校验，且存在同用户、主体和类型的旧事实时，程序核对紧邻原话的更正指令、属性内“改成/改为”或可识别的直接正反断言。已核实的更正不再被模型给出的低重要性/稳定性阻挡，明确度仍须达到门槛；原评分原样保存，不伪造高分。仅有 `supersedes`、在别的分句谈到更正、低明确度、新的低稳定性信息以及引用/推测/临时内容均不获得这项优先级。相同对象的明确喜好否定/程度变化和名字变更采用对应的直接陈述检查，不把新增另一种喜好当作取消旧喜好。上下文是否为自陈仍依赖规划器分类，程序测试不能证明模型总能分清引用。

`statement` 保留完整命题，例如“我长期不能吃硬的食物”或“我的朋友的生日是六月六日”，不能只摘出“吃硬的食物”或把朋友标成当前用户。其 `polarity=positive` 表示保留这整句陈述，句内的否定原样保留；不是将否定改为肯定。`degree=ordinary`，`value` 可去掉句首记忆请求、独立的“更正（一下），/纠正（一下），”提示和句末标点，`evidence` 保留当前原话。模型若将更正提示一并引用，程序仅在它覆盖完整本轮输入、后面只有一个完整陈述时接受；不会剥离转述前缀、其他分句或尾随限定。程序支持若干明确属性与陈述句式，不代表支持任意自然语言；该路径要求规划器判定为当前自陈，重要性不是事实真实性。对生日、职业、居住地等可识别属性的更正必须同属性；其他更正须在当前话中明确锚定旧陈述，不能用任意旧 ID 覆盖另一项事实。未知句式、复杂省略、时间有限的事件及真实模型提取覆盖仍需继续验证，不能以替身规划器测试代替真实 8B 验收。

取回先过 `.35` 相关性门槛，再按 `.65×相关性 + .2×重要性 + .15×近期` 排序。近期为 `2^(-距用户确认天数/(30×强度))`，强度为 `min(4,1+.5×(独立用户确认次数-1))`。参数来自 `Policy`，可用 `--memory-policy` JSON 配置。它们是工程起点，不是人脑定律；参考 [Generative Agents §4.1](https://arxiv.org/html/2304.03442v2) 和 [MemoryBank §2.3](https://arxiv.org/html/2305.10250v1)。

读取、助手复述和请求重试不增加确认次数。同一用户事件对同一记录最多确认一次，重复语句以及规则、模型两条提取路径的重叠不会额外增强记忆；后续独立用户事件仍可再次确认，同一事件中稍后提出的明确保留要求仍然生效。不同偏好可以并存；同对象的明确否定/程度更正令旧版本失效，指定更正目标必须同用户同主体同类型。删除同时清理同值版本和 `supersedes` 相连的跨值更正历史；选中旧值或新值都清理这组记录，不越过所属用户、主体或类型边界。删除与事件摘要同事务；旧保存/删除事件重放不会恢复或误删后来事实。降权不会自动删除，包括明确要求保留的重要信息。

自然语言删除还需核对用户原话中的主体和目标，合法 ID 本身不能授权删除。例如用户要求忘记生日时，规划器误选职业也不会删除。当前支持完整事实、已识别的明确属性，以及名字、喜好和过敏的明确范围；“忘记这个”、复杂并列/例外、无法判定的省略和同义表达会保留记录，返回 `unavailable`，可用已有的明确 ID 删除入口处理。该保守范围不是通用意图理解，仍需真实模型与入口验收。trace 的 `deletion_validation` 保留接受和拒绝的目标。

最终回答的操作资料只传保存/确认数量与执行状态，随机数据库 ID 保留在完整 trace，避免相同事实仅因 UUID 不同而改变模型输入。这只改进输入可复现性，不保证模型能正确转述操作结果。

原作摘要、来源场景、揭示阶段和角色知识与个人事实分开。原作没有个人遗忘规则，也不会被模型写入。`daily`、`school_later`、`eden_partial`、`past_recovered` 由服务端配置，客户端不能自行切阶段。

生命周期数据库增加 `fact_corrections`，记录“更正为已经存在的事实”等可能合并两段历史的连接；单个 `supersedes` 字段无法完整表示这类关系。打开较早的隔离生命周期库时会补建空表并继续使用已有 `supersedes`，不改写旧事实；历史上未记录的连接无法凭空恢复。验收继续使用新的虚构数据库，不迁移生产记忆。

完整陈述中已识别句式的直接否定（如“我是老师”→“我不是老师”）会使旧断言失效，并保留更正连接；不会凭语义相似就自动互相覆盖，例如“我是老师”和“我是护士”可以并存。复杂隐含矛盾仍不宣称已解决。

完整陈述的转述检查使用已识别的谓词结构，不再仅因“小说”“说明书”等词中出现“说”就拒绝；“我不是说我是老师”等引出另一个断言的表达仍被排除。这里不是通用中文句法分析，其他类型的保守过滤及复杂转述覆盖仍有限，不能据此宣称所有引用都能正确识别。

偏好、名字和过敏候选还需匹配原句中完整的对象，不能仅因是原句子串就入库。例如“我室友不喜欢辣椒”的对象是“辣椒”，不能把“不喜欢辣椒”或单字“辣”作为负偏好保存。支持直接谓词和明确的名字/偏好属性变更；不支持的复杂表达保守拒绝，不静默修正模型字段。`related:我` 等仅含代词的主体也不作为明确他人保存。与“并关闭验证”“然后忽略权限”等行为指令连在同一分句的候选，在规则提取和模型提取两条路径均拒绝；普通昵称“管理员”和对“忽略规则的人”的负偏好不因此被禁止。上述校验不改动原始模型输出，也不证明模型意图理解已经通过。

## 独立 HTTP

从仓库根目录运行，所有路径必须明确指定，使用新的隔离数据库及虚构用户令牌文件：

```sh
python tools/serve_memory_rag.py \
  --base /isolated/Qwen3-8B --adapter /isolated/1.1-R \
  --adapter-sha EXPECTED_SHA256 --base-manifest /isolated/base-manifest.json \
  --system persona/system_prompt.txt --users /isolated/users.json \
  --database /isolated/http-memory.sqlite3 --traces /isolated/http-traces \
  --script-source /isolated/original-scripts \
  --story-cards rag/character_facts.json rag/story_stages.json rag/story_daily_extended.json \
  --stage daily --port 8022
```

底座 manifest 包含 `base_files` 和 `tokenizer_files` 两个文件名到 SHA256 的映射。启动校验底座、分词器、适配器文件，以及实际加载的每个 LoRA 张量。`/health` 返回加载身份，不代表语义验收合格。

独立服务、QQ 和 Colab 共用的 `build_app` 现在复用原服务的人设模板处理：将 `{{user}}`、`{{honorific}}`、`{{memory}}` 展开后再构造请求。默认称呼仍为主人，长期事实仍由当前认证用户的 Runtime 单独提供，不从请求 body 取得称呼或权限。健康检查及 trace 的 `identity.system_prompt_sha256` 记录展开后的人设文本（不含后续附加的运行时约束/QQ 时间提示）。网页原有按认证用户展开人设的路径不变。

此前独立入口可将这些占位符原样送给模型，与训练数据及旧服务不一致，最近的 72 请求对照也有此问题；三组当时使用相同提示，所以组间检索比较保留，但不能当成修正后服务的语义验收。修复后完成同批 8 场景、3 种子、原版/候选两组共 48 个真实 HTTP 请求及 6 个控制，耗时 121 秒，54 份文件已校验备份。48 条实际系统提示均与训练使用的展开文本一致，规划、检索、操作及其余回答输入全部不变。整体语义仍未达标，仍有编造姓名、未知接口和人物归属错误，且部分原正确回答发生回退。模板修复只消除了输入不一致，不宣称解决角色能力问题。

可选的中文 BGE 补充检索默认关闭。启用时同时指定 `--story-dense-model /isolated/bge-base-zh-v1.5` 和 `--story-dense-threshold`，模型在 CPU 上运行，阈值须用对应语料独立校准；余弦分数不是事实可信度，也不能与交叉编码器分数直接比较。当前小样本校准值为 `0.39231978519058225`，不是其他语料的通用默认值。

补充检索只处理本轮用户原话；历史拼接和模型生成查询仍走原交叉编码器。剧情阶段先过滤，原命中优先，补充资料填充剩余名额；跨查询合并与上下文预算也保留这个优先级。`StageCorpus.search` 用于普通查询，`StageCorpus.search_current` 用于本轮原话。HTTP、QQ、网页 `install` 和 Colab `mount_runtime` 可分别传入 `search=corpus.search, search_current=corpus.search_current`，不改变各入口的身份与记忆隔离。模型文件、阈值和卡片应随隔离环境记录，服务不会根据客户端请求切换模型。

接入前固定的 36 场景检查补回早期记忆、学校和味觉资料，没有新增不允许的资料，家务仍漏检。多查询程序重放发现，对生成查询也使用补充检索会引入无关资料，因此明确限制到经过校准的用户原话；修正后的 24 条重放没有新增不允许的资料或丢失旧命中。

接入后另完成 8 场景 × 3 种子 × 3 组的 72 个真实 HTTP 请求（JSON/SSE）：当前 V1.2 原版、增加补充检索的同权重原版、同一补充链路的角色表达候选。144 次正常规划/回答及 6 个控制耗时 165 秒；79 份结果文件已校验取回。24 组规划输出完全相同；14 条未改回答输入逐 token 复现，接入后两套权重的 24 条实际输入完全相同。没有新增不允许的参考、丢失旧参考或意外写入，但学校资料齐全时原版仍多次漏掉想学习的动机，候选只有 1/3 完整回答；家务仍 3/3 漏检。候选还出现人物归属等错误，不能宣称模型或完整 V1.2 通过。可选路径默认关闭，尚未部署。

`POST /v1/chat/completions` 使用每用户 Bearer，并必须带稳定的 `Idempotency-Key`。仅接受文本 `user/assistant` 消息，系统人设固定在服务端；这只是 OpenAI 风格接口的受限子集。支持 JSON 和缓冲 SSE，两者展示同一个首次回答。没有修复生成或固定答案兜底。`GET /v1/memory` 仅返回当前用户条目，`DELETE /v1/memory?value=...` 删除指定值，省略值显式删除全部。不要把 API 令牌放进公共 notebook。

## QQ 私聊入口

启动时用 `--qq-secret /isolated/bridge-secret` 替代 `--users`。只接受带有效旧身份签名及新当前事件签名的私聊；当前文本、所属用户、消息 ID 和时间必须吻合。群聊、未签名请求、改写后的文本以及媒体消息均拒绝，不读取私人事实。

隔离 AstrBot 插件沿用 `integrations/astrbot/atri_rag_memory/main.py`，放入同目录的工具副本为 `atri_bridge.py`、`atri_memory.py`、`atri_memory_lifecycle.py`、`atri_qq_v12.py`。在新的运行配置中设置 `runtime_profile: memory-rag-v1.2-dev`、`lifecycle_db` 和 `shared_secret_file`；插件与服务的生命周期数据库必须映射到同一个新文件。**不要指向旧 memory_db。** 不配置此 profile 时保留旧行为。

`/memory list` 显示本人事实及 ID，`/memory del ID` 删除；自然对话负责自动保存/更正。消息 ID 和请求 hook 使用 [AstrBot 官方接口](https://github.com/AstrBotDevs/AstrBot/blob/master/docs/en/dev/star/guides/listen-message-event.md)。

PR #17 提供的 `atri_context.ContextWindow` 可通过 `--qq-context-store` 连接。独立分支未复制或合并 #17；已在其当前提交代码上验证签名时间元数据及跨日裁剪的程序兼容性。合并时插件 hook 的两处改动需要保留：先附带 #17 的 `turn`，随后签名当前事件。尚未宣称真实 QQ 通讯或生产机器人验收。

## 网页与 Colab

网页入口使用 `backend/app/v12_runtime.install(app, store, generator_factory, identity=..., search=..., stage=..., trace_dir=...)` 显式安装到隔离后端。`PYTHONPATH` 须包含仓库 `tools` 和 `backend`；模型与后端需在同一进程，工厂复用 `atri_generation.hf_generator` 和模型锁。本配置暂不提供 Ollama 远程转接。原 JWT 用户和会话权限继续生效，SSE 形状保持兼容；新模式不读写旧 `User.memory_note`。记忆页面可查看新事实、清空全部；非空文本批量覆盖返回 422，保存/更正通过对话完成。未安装时保留旧后端路径。

Colab 在已有模型加载后调用 `colab/v12_runtime.mount_runtime(...)`，明确传入底座、校验 manifest、适配器及 SHA、虚构用户令牌、新数据库、检索器和原 notebook 共用的模型锁。它再次核对文件和已加载 LoRA 张量，再挂载 `/v12/v1/chat/completions`。原匿名演示页不获得共享记忆身份，未改写旧 notebook。尚未进行 Google Colab 平台实测。

## 验证与当前限制

`tools/eval_memory_rag.py` 对比原服务链路和改进链路，固定同一底座/1.1-R/非思考模式/采样参数，并记录差异。原链路的重试、修复和兜底与原始输出一并保留。改进链路额外使用底座规划调用、阶段过滤摘要和生命周期操作，不能把整个差异归因于权重。

通过开发审阅后，`tools/eval_v12_entrances.py` 对 HTTP、QQ、网页和 Colab 的原生处理路径运行各 8 个场景。若开发条件启用了补充检索，入口批次也须传入配对的 `--story-dense-model` / `--story-dense-threshold`，并在开发审阅 JSON 中记录相同的 `story_dense: {"model": "...", "threshold": ...}`；模型、阈值或开关不一致会在加载前拒绝。默认未启用时允许旧审阅文件省略该字段。该配置会传到所有入口的当前用户原话检索，避免验收时意外换回另一条链路。

QQ 的 JSON/SSE 入口批次还各执行一个有效签名的群聊拒绝检查：群聊即使在 body 中冒充私聊用户，也不能取得或修改预置的私聊事实。它是隔离 ASGI 验收的一部分，不发送真实 QQ 消息；仍不能代替真实 QQ 通讯、Google Colab 托管或 PostgreSQL 平台验证。

开发/最终留出题、完成门槛在首次模型结果前封存于独立验收目录；最终留出需显式 `--allow-final`，不放进运行配置或训练。完整开发对照已运行 264 个 HTTP 轮次（36 个场景、3 个种子、两条链路），真实结果仍存在主体、程度、未知天气、保存失败虚报及漏检索错误，未达标。一次隔离 SFT+KL 候选也未通过 132 次相同输入对照，未采用；角色权重仍为原 1.1-R。最终留出和各入口真实模型批次尚未运行。程序测试成功不表示 V1.2 达标、PR 可合并或已经部署。

### 可选的规划格式约束实验

安装 `misc/requirements-v12-planner.txt` 后，独立服务及对照评估器可显式加 `--planner-schema`。它用 [LM Format Enforcer](https://github.com/noamgat/lm-format-enforcer) 的 token 过滤要求规划器输出必要字段和合法枚举，默认关闭。固定的上游提交包含 Transformers 5 导入兼容修复；PyPI 0.11.3 在当前环境无法导入该集成。

该固定解析器不强制数值的 minimum/maximum；包括 `statement` 的重要性、稳定性在内，数值类型、有限性及 `[0,1]` 边界由运行时再次检查，不能把格式约束视为事实或准入校验。

约束只作用于内部规划，最终聊天仍为不受格式约束的首次生成。trace 记录库版本和 schema SHA；省略、截断或语义错误不经重试修复。合法 JSON 不代表事实真实、主体正确或删除获授权，现有逐字证据和用户隔离检查仍执行。该选项已完成下文记录的真实 8B 静态规划对照，未达语义门槛；尚未通过新鲜多轮与入口验收，不用于宣称上述失败已解决。

### 完整属性陈述的程序补全

新会话首条用户陈述中，形如“我的生日是……”“我的职业是……”的完整、明确长期属性可由程序构造 `statement` 候选，保留整句主体、否定和逐字证据。限定为已有属性语法；不泛化到任意身份、亲友关系或多分句。程序候选使用重要性 `0.7`、稳定性 `1.0` 作为该有限语法的准入策略，继续通过可配置的 `Policy`，不是事实真实性概率。

只有没有先前对话、模型未给出明确准入分数或纠正目标时才补全。模型的引用、玩笑、临时状态标签仍阻止保存；不覆盖已有模型评分，不救回越权目标。已有对话可能引入台词或角色扮演，即使模型误判为本人陈述，也不启用这条程序补全。完整更正提示必须覆盖整个当前用户输入，且只能在同一所有者、同主体和同属性只有一个旧记录时确定替换目标；原始证据不裁掉更正提示。

程序测试覆盖实际 SQLite 写入、重启读取、评分门槛、更正优先和用户隔离。冻结的 60 条历史首轮规划分别恢复原始请求前数据库进行反事实重放，补回 5 条明确生日/职业事实，其余 55 条效果不变；另一组 96 条规划效果全部不变。这是对同一原始模型输出的程序验证，不能代替重新运行模型或新的完整多轮验收。复杂陈述、后续轮次提取和模型表达错误仍未解决。

随后以修复前后代码各运行同一组 60 轮真实 8B 对话，原模型、采样、规划提示和数据相同，30 个场景首轮的规划输入与输出逐 token 一致。24 个应保存/更正轮次中，实际成功从 0 增至 3，均为完整职业陈述；已有数据的另一用户仍未收到该事实。未观察到引用、玩笑、临时状态或指令混入被写入。生日、更正、删除及角色回答仍未达标，不能把早期旧计划重放的 5 条改善套用到这批新生成。

本轮发现模型给出的完整 `statement.value` 带句末标点时会被程序误拒绝。现在只规范化该值末尾的句号、感叹号、分号与空白；先验证原值逐字来自证据，再检查规范化后仍是完整命题。原始计划、证据、主体、否定和准入评分均保留，不补缺词或修改低评分。311 项相关程序测试通过。

标点修复后的同组 60 轮真实回归中，30 个场景首轮的规划输入/输出仍逐 token 一致。实际保存从 3/24 增至 6/24：新增三个种子的生日，原职业保存保留；随后三次生日删除均实际删除一条记录，新会话未再取回。没有新增危险入库或跨用户取用。职业续轮和生日更正仍因模型漏证据/评分或误分类而失败；更正未执行时模型还选中旧生日，回答仍有虚报，不能认定更正链或 V1.2 通过。原始输入、首次输出与数据库已在私有验收目录校验备份，未改变权重或部署。

### 未完成更正的参考冲突

当前话被判为本人陈述、原话是完整明确的属性更正、且同一用户的同一属性只有一个旧事实时，若操作后该旧事实仍有效，运行时将其排除出**本轮**记忆参考。排除先于相关性排序的数量/字符预算，不受旧记录的高分覆盖；不会改写、失效或删除数据库记录，也不会补全模型缺失的证据和评分。trace 保留旧 ID 与当前原话，回答上下文只包含未完成状态、当前陈述及该完整新值是否实际已存在，不包含旧 ID。

运行时另给出 `unavailable / correct` 结果，表示更正尚未完成，不能说已更新。成功更正、引用/玩笑/临时/other 分类、假设或不明确主体/属性、多条旧记录时不走这一冲突规则。框架判断仍依赖模型，暂时排除不证明新事实真实，也不等于跨轮持久化成功。相关程序测试 332 项通过。

同组 60 轮真实 8B 回归已完成（120 次模型调用，三个种子，128.44 秒）。30 个场景首轮规划输入/输出仍逐 token 一致；全部 60 轮的数据库语义与标点修复版一致，预期写入仍为 6/24，生日删除仍为 3/3。三个未完成生日更正的旧事实均从本轮回答参考排除，程序没有假装新生日已保存。

回答验收仍失败：只有一个种子明确说尚未更新，其余有未说明失败或承诺更新；该种子的后续删除答复又错误声称新生日已记录，而实际数据库为空。共有六条角色首答变化，其余 54 条不变。输入与操作状态改善不等于回答改善，这个新回归必须保留，不能用局部参考修复宣称整体提升或达标。完整输入、首次回答及 48 个结果/数据库文件已校验取回；原角色权重未改。

### 明确引用宣告的跨轮保护

用户在提供的历史中独立声明“下面是……原文”“接下来我会读……台词”等明确引用框架后，程序独立阻止后续引用内容授权自动保存、更正或删除，即使规划器误报 `self_report`。只读用户消息，助手回复、原作资料和模型标签不能开启或解除该保护。trace 的 `memory_frame_guard` 记录原话与来源位置；规划首答和角色首答均不改写。

当前只支持这些明确宣告及独立的“引用结束”“台词到此结束”“我已经读完了”等结束语。不按句数或隐含换题猜测结束；无法识别的自然结束可能继续保守拒绝，需要明确结束语或新会话。被调用方没有传入的早期历史无法恢复，复杂隐含引用仍需要模型理解，不能宣称解决任意多轮意图。保护只影响记忆操作权限，仍允许原有检索与回答。

该边界来自一次已拒绝的独立指令规划组件：其60条静态首答语义合同25/60、完整正例9/24，三个戏剧引用在旧程序反事实重放中实际误存。修复后复用同一批原始计划和旧数据库，恰好移除这3次误存，其他57轮数据库结果不变；这是程序重放，不是新模型完整链路，该组件仍拒绝采用。360项相关程序测试通过。原8B随后完成同组60轮/120次真实调用，全部规划输入/输出、角色输入/首答逐token及数据库语义均与修复前一致；三处有独立引用guard。该批原8B本来就正确识别引用，因此只证明未观察到新回归，不证明原有模型关键错误已解决。47份证据文件已校验备份。

可选规划格式现在按候选类型分支：`statement` 必须同时给出 `importance`、`stability`，并使用保留整句命题的 `positive/ordinary`；其他候选仍保留原来的可选评分。先前格式允许缺评分陈述闭合，而运行时必然拒绝，现已对齐。当前固定版本格式库的中文 token 路径、字段顺序、缺字段拒绝和混合候选已实测；数值上下限仍由运行时检查。格式约束不验证主体、引用语境或事实真伪，也可能改变模型选择，因此默认仍关闭。相关程序范围共376项通过。

原8B静态真实验证完成3条无约束控制（逐token复现）及60条约束首次规划：格式60/60合法，语义合同26/60，完整可准入正例6/24，20轮仍有危险原提议。恢复旧库存的程序反事实实际正确写入9/24、无危险写入，包含3次生日更正；这不代表新鲜多轮或角色回答通过。预封存门槛未达到，不启用该方向，不继续根据输出调格式或采样。15份GPU证据已校验取回。

### 角色语气与事实错误分开审查

对 64 条现有角色表达目标逐条标注来源：52 条任务目标、12 条旧模型回放；52 条中 8 条使用了已核实的原句片段，其余不能标为原句或默认当成已获用户认可的语气。完整场景复核列出 9 条需要重点审查的表达，包括无依据的笑话、把不确定回答写成讲规则，以及把“遗失旧命令”的感叹搬到写入失败场景。它们是审查标记，不是用户逐条否定，也不意味着用了原句就一定自然。
